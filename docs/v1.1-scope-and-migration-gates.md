### Proposed additive My Stuff data model (review only)

#### Required domain separation

- My Stuff uses new `my_stuff_*` tables; it does not reuse or extend `projects`, `expenses`, `trade_up_goals`, or `goal_ledger`.
- No My Stuff table has a foreign key to a project, expense, Trade-Up Goal, or goal-ledger entry.
- My Stuff maintenance costs do not change project investment, profit, ROI, goal progress, available goal funds, or sale/Undo Sale accounting.
- Projects and goals do not query or depend on My Stuff records.
- The only shared references are `auth.users` for ownership/account deletion and the existing authoritative Pro-entitlement helper for item-creation eligibility.
- A My Stuff failure or future rollback therefore cannot corrupt or delete project/goal data.

No backfill is required because this is a new feature.

1. `my_stuff_items`
   - Owner-scoped UUID primary key and `user_id` foreign key to `auth.users` with `on delete cascade`.
   - Name, item type/category, optional acquisition date and notes.
   - Current mileage and operating hours, each finite and non-negative.
   - Idempotent `client_mutation_id`, unique per owner.
   - Created/updated timestamps and owner/count indexes.
2. `my_stuff_schedules`
   - Owner and item foreign keys with cascading deletion.
   - Maintenance name and one tracking mode: `mileage`, `hours`, or `calendar`.
   - Positive interval, last-service reading/date, and next-due reading/date with mode-specific checks.
   - Indexes for item ordering and due-state lookup.
3. `my_stuff_service_logs`
   - Owner, item, and optional schedule foreign keys with cascading deletion.
   - Completion date, optional mileage/hours snapshot, notes, and optional non-negative cost.
   - Index for reverse-chronological item history.

### Proposed authorization and entitlement enforcement

- Enable RLS on all three tables.
- Owner-only select, update, and delete policies use `(select auth.uid()) = user_id`.
- Child writes additionally verify that the referenced item belongs to the authenticated owner.
- Revoke direct authenticated inserts into `my_stuff_items`.
- Create one authenticated `create_my_stuff_item(...)` RPC that:
  1. Resolves the owner exclusively from `auth.uid()`.
  2. Requires a mutation ID and returns the existing item on an idempotent retry.
  3. Acquires the same per-user advisory transaction lock used by Trade-Up Goals.
  4. Calls the existing `user_has_verified_pro_entitlement(user_id)` helper.
  5. Rejects item number two or later when authoritative Pro is absent.
  6. Validates fields and inserts the owner-scoped row atomically.
- Add a defensive trigger using the same lock and entitlement helper so future write paths cannot bypass the limit.
- Do not hide, lock, or delete existing rows after downgrade. Downgraded users may view, maintain, update, export, or delete existing items; only additional item creation is blocked.
- Android continues to consume authoritative Pro only. No local Pro flag, external checkout, Restore Purchases control, or Google/Apple purchase workaround is added.

### Account deletion and storage

- Cascading foreign keys remove items, schedules, and logs when the Auth user is deleted.
- V1.1 stores no My Stuff files, so no new storage bucket or cleanup path is proposed.
- If item photos are requested later, that requires a separate storage/RLS/deletion review.

### Rollback

- Before public release, rollback can remove the new RPC, trigger, policies, and empty tables.
- After user data exists, rollback must preserve tables/data and only disable entry points; destructive table removal is not acceptable.
- Existing project, expense, goal, entitlement, Apple, and Stripe objects are not altered.

### Required verification

1. Free user creates item one successfully.
2. Free user item-two attempt is rejected by both UI and RPC.
3. Authoritative Pro creates additional items.
4. Concurrent Free item creation results in exactly one item.
5. Mutation retry does not duplicate an item.
6. Cross-account reads and writes fail under RLS.
7. Pro downgrade preserves every existing item and maintenance record while blocking new creation.
8. Deleting the sole Free item restores one-item creation eligibility.
9. Mileage, operating-hours, and calendar schedules validate and calculate due state correctly.
10. Account deletion cascades all My Stuff records.
11. Existing project/goal/accounting and entitlement regressions remain green.
